# Ambition surface recipes

Use this after `ambition-calibration-contract.md`, `surface-playbook-matrix.md`, and `capability-recipe-cookbook.md` when Stark knows the product surface but still needs a concrete "what do we maximize?" recipe before implementation.

This is the bridge between ambition and build choices. Pick one recipe, name the two dimensions that get the most craft, and keep every other choice in service of the product job.

## Recipe rules

- A high ambition level does not mean more effects. It means the right two dimensions get sharper proof.
- Use the target level from ambition calibration. Do not silently downgrade a public "next level" request to ordinary polish.
- Use the surface playbook's library ceiling. If a recipe needs more libraries, write the removal rule before coding.
- For repeated-use UI, maximize speed, state coverage, density, and recovery before cinematic expression.
- For public proof, maximize first-read product object, proof credibility, type/copy, and rendered evidence before broad feature count.
- If the result starts to feel like a collage, delete supporting effects before changing the main object.

## Recipes

### AI Generation Launch Or Cinematic Product Proof

- Target level: high-craft or portfolio.
- Maximize: asset/proof depth + motion depth.
- Structure: one generated-output object, prompt/input proof, transformation moment, gallery or before/after proof, conversion path.
- Typography: expressive display for the promise, quiet UI/body, mono for prompts, seeds, model states, or logs.
- Motion: one authored prompt-to-output, material reveal, object birth, or scroll proof sequence; reduced-motion stills must preserve the proof.
- Libraries: CSS + Motion or GSAP; add Three/R3F, Rive, Lottie, video, or canvas only if it owns the main proof object.
- Assets: produced key art, product mock, generated output, video/poster, or code-rendered artifact with DOM-owned text and controls.
- Usability proof: prompt/edit path, generation failure, output inspection, mobile proof frame.
- QA: desktop/mobile screenshots, nonblank media/canvas, reduced-motion frames, poster/proof/end frames, copy quality, benchmark repair.
- Reject: copied phone-prop scenes, floating AI symbols, unrelated animated props, generic "create anything" copy.

### Developer Tool, SDK, Or Docs Product Proof

- Target level: polished or high-craft.
- Maximize: product proof/data depth + typography/code depth.
- Structure: docs/console split, command workbench, request/trace/artifact proof, install path, failure/recovery state.
- Typography: precise UI sans, strong mono, tabular data where logs or metrics align.
- Motion: route/detail continuity, command palette, artifact arrival, copy feedback; no scroll theater unless it is a launch page.
- Libraries: cmdk/search, Radix or React Aria for overlays, Query for live/server state, Motion for continuity.
- Assets: real-looking snippets, logs, diff, request, trace, artifact, or package manifest.
- Usability proof: search/copy/install path, error state, keyboard command path, mobile docs/proof replacement.
- QA: code overflow/copy, keyboard/focus, console health, mobile nav, text stress, implementation review.
- Reject: fake terminal wallpaper, unreadable code, giant feature cards, generic dark SaaS gradients.

### Operational Dashboard Or CRM

- Target level: polished; high-craft only when public proof demands it.
- Maximize: usability depth + product-library depth.
- Structure: queue or saved-view cockpit, table/list, exception logic, bulk action, detail inspector, timeline/audit trail.
- Typography: compact UI sans, tabular figures, restrained headings, clear status labels.
- Motion: state feedback, row/detail continuity, optimistic or async status arrival.
- Libraries: TanStack Table/Query when records are real, Radix/React Aria for menus/dialogs, RHF/Zod for editable flows.
- Assets: realistic domain fixtures, statuses, owners, dates, money, freshness, source labels.
- Usability proof: returning-user speed path, bulk action recovery, stale/error/permission states, keyboard row/action path.
- QA: table overflow, saved filters, long labels, mobile detail sheet, rendered usability acceptance, accessibility acceptance.
- Reject: marketing spacing, animated KPI vanity, hover-only controls, decorative charts without decisions.

### Editor Or Creative Canvas

- Target level: polished or high-craft.
- Maximize: interaction depth + component anatomy.
- Structure: dominant canvas/work surface, stable tool rail, layers/timeline, inspector, export/save path.
- Typography: quiet UI sans, mono for coordinates/properties, minimal display type.
- Motion: direct manipulation feedback, selection continuity, inspector/sheet transitions; primary controls stay stable.
- Libraries: Motion for layout continuity, Radix/React Aria for menus, cmdk for expert actions, canvas/Pixi/R3F only if it is the work surface.
- Assets: editable object, layer set, timeline frames, export preview, conflict fixture.
- Usability proof: select/drag/resize, undo/redo, save conflict, keyboard alternative, touch/mobile replacement.
- QA: canvas framing, pointer/keyboard paths, inspector overflow, reduced motion, performance budget.
- Reject: decorative chrome, moving controls, empty canvas, effects that change hit targets.

### Agent Run, Automation, Or Build Review UI

- Target level: polished or high-craft.
- Maximize: state coverage + artifact proof.
- Structure: run timeline, current step, tool/log detail, artifact inspector, stop/retry/resume controls.
- Typography: UI sans for status, mono logs, compact status chips with accessible labels.
- Motion: artifact/status arrival and continuity only after work is produced.
- Libraries: Query/server state, Motion for arrivals, Radix dialogs/menus, cmdk actions.
- Assets: logs, artifacts, diffs, screenshots, test results, blocked approval state.
- Usability proof: queued/running/waiting/blocked/failed/retrying/succeeded paths, stop/retry focus path.
- QA: live/status text, log readability, mobile artifact sheet, keyboard controls, rendered usability acceptance.
- Reject: spinner-only states, celebration before output, vague "thinking" copy, hidden failures.

### Checkout, Permissions, Trust, Or Install

- Target level: polished or high-craft.
- Maximize: usability/recovery depth + accessibility depth.
- Structure: decision summary, scope/price/risk matrix, review step, confirmation, failure/rollback path.
- Typography: plain trustworthy UI, clear numerals, readable legal/risk copy, no novelty near consequence.
- Motion: level 0-1 feedback; never hide errors, terms, scopes, prices, or destructive consequences.
- Libraries: RHF/Zod or native validation, Radix/React Aria dialogs, Query for pricing/session state.
- Assets: permission scopes, audit events, invoice/plan details, compatibility status.
- Usability proof: validation, denied/revoked/payment failure, preserved input, cancel/escape path.
- QA: focus order, contrast, target size, error recovery, keyboard-only, mobile review, accessibility acceptance.
- Reject: one-click trust, playful motion, vague scopes, hidden cancellation, color-only status.

### Analytics Or Data Product

- Target level: polished or high-craft when public proof matters.
- Maximize: data decision depth + source/interaction proof.
- Structure: chart-as-object, question/title, filter/focus controls, source table, exception list, export/share.
- Typography: tabular figures, clear units, compact annotations, restrained headings.
- Motion: filter/reveal/focus changes only when causality becomes clearer.
- Libraries: ECharts for dense ops, D3/visx for bespoke interaction, Observable Plot/Vega-Lite for grammar exploration, TanStack Table/Query for source/drilldown.
- Assets: realistic dataset, source labels, freshness, outliers, no-data state, accessible summary.
- Usability proof: user question answered, drill path, table fallback, export, mobile chart replacement.
- QA: chart/source labels, color independence, tooltip/focus, no-data/outlier states, accessible summary.
- Reject: decorative chart variety, unsourced metrics, animated KPIs without decisions.

### Showcase, Gallery, README, Or Portfolio Proof

- Target level: portfolio.
- Maximize: asset/proof selection + QA depth.
- Structure: curated examples, comparison baseline, rejected examples, repair candidates, captions, detail inspection.
- Typography: caption-led clarity, quiet UI, display only for gallery identity.
- Motion: one inspection transition or scroll snap with controls; essential content is not autoplay-only.
- Libraries: CSS first, Embla or View Transitions only when inspection improves, Motion for detail continuity.
- Assets: high-resolution screenshots, mobile crops, before/after, benchmark gap record.
- Usability proof: keyboard gallery controls, captions explain product job, mobile inspection path.
- QA: selected/rejected evidence, desktop/mobile crops, rendered quality, screenshot-worthiness, regression baseline.
- Reject: publishing every output, weak examples beside strong ones, cropped product proof, vague sample labels.

## Stop and continue

Stop when the rendered evidence proves the chosen recipe at the target level and adding more would only add novelty.

Continue when:

- the maximized dimensions are not visibly stronger than the quiet dimensions
- the structural recipe is generic for the product surface
- a library is present but does not own a user-visible behavior or proof object
- mobile, reduced motion, or usability evidence loses the main proof
- the rendered result still reads as a template, collage, presentation, or starter kit

## Hard fails

- No recipe is chosen for a high-craft, portfolio, library-heavy, or broad "next level" request.
- The selected recipe contradicts the surface playbook.
- More than two dimensions are maximized without a removal list.
- A repeated-use product is treated as a cinematic campaign.
- A public proof surface lacks produced proof assets or rendered QA.
- The library ceiling is exceeded without a reason, owner map, and removal rule.
